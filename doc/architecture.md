# Architecture

How Flee turns expression text into a delegate, for whoever works on the library. Figures and the
history of the code base are in [flee-project-findings.md](flee-project-findings.md).

## Pipeline

```
text ──parse──▶ element tree ──emit──▶ IL in a DynamicMethod ──▶ delegate ──▶ Evaluate()
       (Parsing)  (ExpressionElements)   (FleeILGenerator)        ExpressionEvaluator<T>
```

`Expression<T>` (`src/Flee/InternalTypes/Expression.cs`) runs it, from its constructor:

1. **Copy the context.** `ExpressionContext.CloneInternal(false)` copies options, parser options
   and imports; variables stay shared. Later changes to the original context do not affect the
   compiled expression.
2. **Set up options.** The owner's type is recorded and its members imported
   (`ExpressionImports.ImportOwner`).
3. **Parse.** `ExpressionContext.Parse` runs the parser under a per-context lock. The parser is
   generated by Grammatica from `src/Flee/Parsing/Expression.grammar`; its analyzer
   (`CustomExpressionAnalyzer.cs`, class `FleeExpressionAnalyzer`) builds expression elements
   directly in its callbacks, so there is no separate syntax tree. Name resolution and type checking
   happen here, as the elements are constructed and resolved.
4. **Wrap.** The top element is wrapped in a `RootExpressionElement`, which converts the result to
   the requested result type.
5. **Emit.** A `DynamicMethod` with the signature
   `(object owner, ExpressionContext context, VariableCollection variables)` is created and the
   tree emits IL through `FleeILGenerator`. Branches are first emitted in their short form; if any
   turns out to be too far, the whole tree is emitted a second time with long branches
   (`BranchManager`).
6. **Delegate.** The method becomes an `ExpressionEvaluator<T>`; `Evaluate()` calls it with the
   owner, the context and the variables.

The runtime JIT-compiles the method on its first call, not during step 5. That is why the
benchmarks measure `CompileAndEvaluate` separately.

## Elements

- `ExpressionElement` (`ExpressionElements/Base`) is the base: `ResultType` and
  `Emit(ilg, services)`. Intermediate bases: `BinaryExpressionElement`, `UnaryElement`,
  `MemberElement`, `LiteralElement`.
- One class per construct: arithmetic, compare, and/or, xor, not, negate, shift, `in`, `if`
  (`ConditionalElement`), `cast`, literals per type, identifiers, function calls, indexers.
- Compile-time context reaches elements through an `IServiceProvider` holding the options, the
  parser options, the context and an `ExpressionInfo` (`Expression.AddServices`).
- Implicit conversions and the result type of mixed arithmetic come from tables in
  `ImplicitConverter`. Overloads are chosen by scoring each candidate's conversions
  (`CustomMethodInfo`); user-defined operators are found with custom reflection binders.

## Members and names

`MemberElement` and its subclasses resolve names: owner members and imported static members first,
then variables, then calculation-engine atoms (`IdentifierElement.ResolveInternal`). At run time:

- variables are read through `VariableCollection.GetVariableValueInternal<T>`, on-demand functions
  through `GetFunctionResultInternal<T>`, virtual (TypeDescriptor) properties through
  `GetVirtualPropertyValueInternal<T>`;
- calculation-engine atoms through `ExpressionContext.CalculationEngine` and
  `CalculationEngine.GetResult<T>`.

These helpers are marked `NoInlining`, because .NET 10's JIT otherwise copies them into every
generated method and the first call of each expression becomes slow (R-019).

## Calculation engine

`CalculationEngine` (`src/Flee/CalcEngine`) keeps atoms in a `DependencyManager`: a graph from
each atom to the atoms that use it. `Add` registers a temporary head for the new name, compiles
the expression with the engine attached to the context (so names of other atoms resolve to them
and are recorded as dependencies), then replaces the head with the typed result pair and
evaluates it. `Recalculate` evaluates the given atoms and their dependents in dependency order.

## Parser

`src/Flee/Parsing` is a private copy of the Grammatica runtime (tokenizer, regular-expression
engine, LL parser) plus the generated `ExpressionParser`, `ExpressionTokenizer`,
`ExpressionAnalyzer` and `ExpressionConstants`, and Flee's own analyzer and token patterns. Only
`ExpressionContext`, `ExpressionCompileException` and the calculation engine's
`IdentifierAnalyzer` use it. It is not changed before the first release; parser work is listed in
[deferred.md](deferred.md) (D-01 to D-04).

## Tests and measurements

- `test/Flee.Test/ScriptTests`: the 1,756 script cases from `TestScripts`, one test each.
- `test/Flee.Test/DocumentationTests`: the examples of the language reference and the API guide.
- Fixture tests, many ported from the original VB.NET test project.
- `benchmarks/Flee.Benchmarks`: parse, compile, compile-and-first-call and evaluate per vector, on
  .NET 6, 8 and 10; results in `benchmarks/results`.
